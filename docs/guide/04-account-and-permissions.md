# 账号与权限

## 注册与登录

注册只需要邮箱与密码：密码至少 6 位且同时包含字母和数字，要求输入两次一致；提交后系统向邮箱发送 6 位验证码，在账号页面输入完成注册（注册入口在投稿页、列表页和账号页都有，未确认时都会引导到账号页的验证码面板）。自托管实例的邮件出站走 QQ 邮箱 SMTP。作者身份即账号本身，不要求绑定 git 或 GitHub 账号。账号以内部用户 id 为键，邮箱只是登录凭据，改名下的 pack、组织和投稿记录都不受影响。

修改密码在 `/account.html` 上完成：先验证当前密码，新密码遵守同样的复杂度规则并要求双输确认，然后由浏览器直接调用 Supabase 的 `PUT /auth/v1/user` 轮换，市场服务端不参与。

修改邮箱也在 `/account.html` 上完成：先验证当前密码，再填写新邮箱，系统向新邮箱发送 6 位验证码，输入后变更生效，下次登录用新邮箱。改邮箱只验证新邮箱单侧（实例关闭了双端确认）。忘记密码走登录页的恢复链接邮件。

## 发布者组织

每个账号可以设置一个发布者组织（org）：小写 kebab-case，全站唯一，少量保留名不可用。组织展示在目录、详情页与安装索引中，是 pack 的发布者身份。

- 首次投稿前必须设置组织，否则投稿被拒绝。
- 修改组织是账号页上的独立操作：系统先列出该账号名下会受影响的 pack 数量，确认后在一次事务内完成账号改名与全部 pack 的改标。
- 组织在投稿审核通过时盖到 pack 上；审核通过后后续更新不受作者此后改组织的影响。

## 管理员

管理员是 `profiles.is_admin` 为 true 的账号，首任管理员由部署者手工指定。管理员的权限仅限审核队列：查看队列、通过或拒绝投稿。pack 的属主操作（修改元数据、下架等）与管理员身份无关，只有属主账号可以执行。

## 作者对自己 pack 的管理

作者在账号页通过 `/api/my/*` 端点管理自己的 pack，操作以属主身份鉴权：

| 操作 | 行为 |
|---|---|
| 修改元数据 | 更新 category、license、homepage、author；description 与 manifest 绑定，只能随新版本投稿更新 |
| 下架 / 恢复 | 下架后 pack 从目录与安装索引隐藏，tarball 下载返回 410；期间审核通过的新版本不会自动恢复上架；可随时恢复 |
| 硬删除 | 移除目录条目、版本历史与存储中的 tarball，名字释放可重新注册；投稿历史保留，同名同版本号永久不可复用 |
| 撤回投稿 | 删除仍处于待审状态的投稿 |

## 属主锁定

投稿的属主账号在该 pack 首次发布时锁定，此后对该 pack 的一切更新必须来自同一账号，防止冒名投稿。
