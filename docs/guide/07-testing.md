# 测试体系摘要

测试分三层，加上消费端安装器的用例，入口集中在 `scripts/test.sh`（单元与覆盖率）与 `scripts/e2e/run.sh`（端到端场景）。

## 层次

| 层 | 工具 | 覆盖对象 |
|---|---|---|
| 校验器单元测试 | vitest | 校验器的 HTTP 端点、形状规则、解包安全、内容哈希；附行覆盖率门槛 |
| 安装器测试 | vitest | `install.mjs` 的退出码、落盘结果、全部完整性拒绝路径、钉版安装 |
| 服务端单元与集成测试 | cargo test + sqlx::test + wiremock | 投稿规则全集、发布与版本历史、审核、目录读侧、组织与属主管理、认证拒绝路径 |
| 端到端场景 | `scripts/e2e/*.sh` | 打真实部署集群的完整业务场景 |

## 端到端场景

每个场景独立注册账号、自建数据，结束时不留残留；可以单独运行，也可以全套运行。

| 场景 | 钉住的行为 |
|---|---|
| 01-happy | 设组织、投稿、机器校验通过、审核、上架，目录与安装索引一致 |
| 02-rules | 各条机器强制规则的拒绝行为与状态码 |
| 03-consumer | 安装最新版与钉版、完整性拒绝、重装冲突 |
| 04-owner-org-versions | 组织改名级联、版本历史与旧版下载、元数据修改、下架恢复、撤回、硬删除 |
| 05-password | 修改密码后旧密码失效、新密码可登录 |
| 06-suites | 套件投稿、审核、目录展示 |
| 07-web-pages | 各页面的基本可用性 |

## 运行

```sh
scripts/test.sh                # 全部单元与集成测试（含覆盖率门）
scripts/e2e/run.sh             # 全部端到端场景（默认打生产集群）
scripts/e2e/run.sh --only 03   # 单个场景
scripts/e2e/run.sh --local     # 宿主进程模式，集群部署前使用
```

服务端集成测试需要可达的 Postgres，`scripts/test.sh` 会自动建立端口转发。

## 约定

单元测试以行为命名测试用例；端到端场景互相独立，不依赖其他场景留下的数据；覆盖率门槛只升不降；新增拒绝路径的断言要指明拒绝落在哪条规则上，而非只断言状态码。
